# GenU コーディング規約ガイド

## プルリクエストポリシー（必須遵守）

- **Kiroが勝手にプルリクエストを作成することは禁止です**
- コーディング内容を整理し、プルリクエストの内容（変更ファイル一覧、変更概要、目的）をユーザーに表示してください
- ユーザーが明示的に承認した場合のみ、プルリクエストの作成を実行してください
- 承認前にプルリクエストを作成した場合、それは規約違反です

## 概要

このステアリングファイルは、AWS Samples の Generative AI Use Cases (GenU) プロジェクトにおけるコーディング規約に関する情報をまとめています。プルリクエスト #1390 で追加されたコーディング標準に基づいています。

## コーディング標準

GenU プロジェクトでは、コードベース全体の一貫性、保守性、品質を確保するために、パッケージごとに専用のコーディング規約を定めています。

### 重要な言語規約

#### コメントとドキュメント

- **すべてのコードコメントは英語で記述する**: GenUプロジェクトは国際的なオープンソースプロジェクトのため、コメントは英語で統一されています
- **JSDocコメントも英語で記述する**: 関数やクラスの説明は英語で記述してください
- **変数名・関数名は英語**: 既存のプロジェクト規約に従い、識別子は英語で命名してください

#### 文字列とメッセージ

- **ハードコードされた日本語文字列は禁止**: UI表示用の文字列は国際化（i18n）対応のため、翻訳キーを使用してください
- **エラーメッセージは英語**: ログやエラーメッセージは英語で記述してください
- **デバッグ用console.logも英語**: 開発時のログメッセージも英語で統一してください

#### 型安全性

- **`any`型の使用禁止**: TypeScriptの厳密な型チェックを活用し、適切な型を定義してください
- **明示的な型定義**: 関数の引数と戻り値には明示的な型を指定してください

### パッケージ別コーディング規約

コードを貢献する際は、以下の各パッケージのコーディング規約に従ってください：

#### 1. CDK インフラストラクチャ

- **ファイル**: `packages/cdk/CODING_RULES.md`
- **対象**: AWS CDK を使用したインフラストラクチャコード
- **内容**: CDK スタック、コンストラクト、リソース定義に関する規約

#### 2. バックエンド API (Lambda)

- **ファイル**: `packages/cdk/lambda/CODING_RULES.md`
- **対象**: Lambda 関数のバックエンドコード
- **内容**: API エンドポイント、ビジネスロジック、データ処理に関する規約

#### 3. フロントエンド (React)

- **ファイル**: `packages/web/CODING_RULES.md`
- **対象**: React を使用したフロントエンドコード
- **内容**: コンポーネント設計、状態管理、UI/UX に関する規約

## 貢献時の注意事項

### 事前確認

1. 変更対象のパッケージに対応するコーディング規約を必ず確認する
2. 既存のコードスタイルと一貫性を保つ
3. プロジェクトの標準に合わせてコードを作成する

### 品質保証

- **一貫性**: コードベース全体で統一されたスタイルを維持
- **保守性**: 将来の変更や拡張を考慮した設計
- **品質**: テスト可能で読みやすいコードの作成

## 実装時のベストプラクティス

### 1. コード作成前

- 該当するコーディング規約ドキュメントを熟読
- 既存の類似実装を参考にする
- プロジェクトの設計パターンを理解する

### 2. コード作成中

- 規約に従った命名規則を使用
- 適切なコメントと文書化を行う
- エラーハンドリングを適切に実装

### 3. コード作成後

- リンティングツールでコードをチェック
- テストを実行して動作を確認
- プルリクエスト前にコードレビューを実施
